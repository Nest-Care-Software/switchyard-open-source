# Source preview

Allocation and production mappings remain disabled. The checked-in owner,
repository, tenant, subscription, application and storage identities are fictional
examples. They aren't evidence that a deployment exists or has been approved.

Before using Switchyard, review and replace the complete identity configuration,
pin workflows and the allocation action to reviewed commits in your repository,
and collect the live evidence required by the trust and recovery documentation.
Keep every approval, identity, reservation, deadline and cleanup check. Never
enable a mapping merely to make an example run.

The source has fresh history. Deployment records, original commit attribution,
issues, workflow logs and artefacts aren't part of this copy. Public vendor
identifiers, dependency metadata and third-party action pins remain unchanged.
